# 곰같은여우의 마법정원 — 첫 플레이 프로토타입

2026-10-27 / Magic Garden 기획 v0.1을 바탕으로 한 **마을 → 텃밭 → 조합 실험실 → 몬스터 연구소** 작동 검증용 게임.

## 실행

Node.js 및 npm 필요.

```bash
cd MagicGarden
npm install
npm run dev
```

빌드: `npm run build`, 로컬 확인: `npm run preview`

## 구현된 기능

- 터치/클릭 위치로 여우 이동, 귀여운 4마리 동물 캐릭터 (고해상도 원화 WebP 아틀라스, 로딩 실패 시 Canvas 대체)
- 4마리 동물 클릭/터치 대화 및 연관 구역 바로 이동, 이동 지점 링 표시와 1장 원화를 이용한 좌우 방향 전환·걸음 애니메이션
- 중앙 마을 / 큰 텃밭 / 조합 실험실 / 몬스터 연구소 네 구역 원화 전환과 상황 안내
- 12개 텃밭에 파종·성장·수확 (18초 단축 실험 속도)
- 씨앗·열매 재고, 가방·도감·도움말, 지역 지도에서 4개 구역 바로 이동
- 조합 실험실의 열매→마법 정수→알 제작 및 몬스터 연구소의 30초 부화 기초 루프
- 가방에서 JSON 저장파일 내보내기·형식 검증·적용 전 확인을 거친 불러오기
- 팝업 내부 상태/재료 부족 안내 및 모바일 버튼 배열 보강
- 캐릭터와 밭을 동일한 발 좌표 기준으로 깊이 정렬, 원거리 캐릭터는 약간 작게 표시(배경 원화 개별 오브젝트 가림과는 다름)
- 브라우저 로컬 저장(프로토타입 단계), 모바일 세로 화면 카메라 추적
- 앱 소스/배포 자산에 벡터 이미지가 섞이지 않는 검사 스크립트

## 고품질 원화 적용 (2026-10-27)

- `public/assets/town-scene-v1.png` — 마을, 폭포, 물레방아, 다리, 오솔길 고화질 원본 비트맵
- `public/assets/farm-scene-v1.png` — 넓은 텃밭, 숲, 풍차, 농가 고화질 원본 비트맵
- `public/assets/town-scene-v1.webp` · `farm-scene-v1.webp` — 기존 두 배경의 모바일용 최적화 사본 (각 약 570KB · 463KB)
- `public/assets/lab-scene-v1.webp` · `nursery-scene-v1.webp` — 색유리·마법 솥이 있는 조합 실험실과 동화풍 알 둥지가 있는 부화실 원화 (각 약 371KB · 329KB)
- `public/assets/friends-atlas-v1.webp` — 여우(초록 가방)·곰(푸른 앞치마)·고양이(분홍 목도리)·토끼(보랏빛 소품) 투명 배경 2×2 원화 스프라이트. 1312×1199, 약 269KB. 네 친구가 하나의 GPU 이미지 자원을 공유하며, 배경과 별도로 비동기 로딩된다.
- 마을과 밭에 작은 나비·햇살 먼지, 실내 공간에 반짝이는 빛 입자, 친구들의 숨쉬기·살짝 기울기·걷기 동작을 더했다. 해당 연출은 기존 클릭을 가로채지 않으며 `prefers-reduced-motion` 이용자에게는 움직임을 제한한다.
- 각 구역에 진입할 때에만 해당 WebP 원화를 비동기 로드한다. 다운로드를 못 하는 경우에는 기존 절차적 Canvas 배경으로 작동한다.
- 실외 2개·실내 2개 배경은 단일 이미지이므로 캐릭터·밭 오브젝트의 간단한 깊이 정렬은 구현했지만, 배경의 자연물·건물과 캐릭터 사이 **완전한 앞뒤 가림(오클루전), 지형 충돌, 실제 3D 카메라**는 구현되지 않았다. 다음 단계에서 레이어 분리와 충돌 지도를 제작한다.
- 모바일에서 실제 로드하는 배경 4장 + 캐릭터 아틀라스의 파일 합계는 약 2.0MB다. 원본 PNG 2장은 향후 편집용으로 계속 보존되며, 브라우저에서 참조하지 않는다.
- `vite.config.ts`에 `base: './'`을 넣어 AI 놀이터 하위 경로에서 정적 파일 경로가 유지되도록 했다.
- 이미지 제작 방식: 이미지 생성 도구 기반 자체 게임 배경 원화 4장과 시그니처 동물 아틀라스 1장. 원화 편집·배포는 비트맵 PNG/WebP만 이용.

## 상호작용·연출 보강 (2026-10-27, v3)

- 텃밭 12칸의 표시를 각진 사각형 버튼에서 작은 흙 둔덕으로 바꾸고, 재배 원화 위에 낮은 투명도와 넓은 터치 판정(166×105 게임 좌표)을 사용한다. 재배 칸 위치를 큰 흙밭의 중앙 쪽으로 재정렬.
- 작물은 새싹 → 잎 성장 → 열매 형성 → 수확 준비 순서로 높이·잎 크기·열매 크기가 자연스럽게 바뀐다. 수확 준비 시 부드러운 빛 테두리·흔들림으로 안내한다.
- 파종·수확·정수 조합·알 제작·부화 성공에 PixiJS 비트맵/WebGL 기반 소량의 반짝임 효과를 재사용하고, 입자 수를 제한(최대 72개)해 메모리와 연산량을 통제한다.
- 부화 중에는 현재 남은 초·진행률 막대·활성화되는 버튼이 약 0.5초 간격으로 갱신된다. 기존의 30초 실시간 부화와 저장 데이터 구조는 그대로 유지한다.
- 기존 캐릭터 모션·효과와 새 작물 흔들림은 사용자의 `prefers-reduced-motion` 설정을 존중한다. 웹 게임의 SVG 이미지 금지 정책을 유지한다.
- 자동 TypeScript·Vite·원화 PNG/WebP·SVG 금지 검사 통과. 실제 화면에서 텃밭 12칸의 누름 판정과 작물 크기, 부화 카운트다운 반응은 실기기 QA 필요.

## 캐릭터 1방향 고정 연출 (2026-10-27, v4)

- **여우·곰·고양이·토끼 4종은 언제나 제작된 정면에 가까운 3/4 방향 그대로 유지.** 좌·우 이동 때 이미지를 뒤집지 않아 여우 가방, 곰 앞치마, 고양이 목도리, 토끼 파우치의 위치와 원화 원칙을 보존한다.
- 여우의 실제 이동 목표 좌표와 경로 계산은 종전대로 동작. 움직임은 부드러운 좌우 몸 기울기(최대 약 2도), 발걸음에 맞춘 작은 늘임·눌림, 바운스로 구분한다. 앞모습 한 장을 쓰므로 뒤로 걸어갈 때도 얼굴이 보이는 의도된 동화풍 표현이다.
- 네 캐릭터 발아래의 작고 부드러운 그림자를 바닥에 추가해 위치·높낮이와 공간감을 강조. 캐릭터보다 뒤의 깊이로 정렬하고 클릭을 차단하지 않게 설정.
- 캐릭터별 4방향/8방향 원화 제작·다운로드가 필요 없어 모바일 리소스를 늘리지 않는다. 이동 속도·가방·저장 데이터·텃밭 12칸·부화 로직은 바꾸지 않는다.

## 이동 방향이 눈에 보이도록 보정 (2026-10-28, v5)

- v4의 실제 문제: 캐릭터의 이동 목표는 동작했지만 원화 방향이 고정됐고 몸 기울기도 최대 약 2도라 좌우 이동의 차이를 알아보기 어려웠다.
- 여우가 왼쪽으로 이동하면 같은 3/4 전면 원화를 좌우 반전, 오른쪽으로 이동하면 원래 방향으로 되돌린다. 위아래로 움직일 때는 마지막 좌우 방향을 유지하고 몸의 앞뒤 눌림과 발걸음으로 이동감을 준다. **별도 뒷모습 원화가 없으므로 위로 이동해도 실제 등 뒷모습은 보이지 않는다.**
- 이동 시간을 기준으로 흔들던 걷기 모션을 실제 이동 거리 기반의 발걸음 주기로 변경했다. 걸을 때에만 약간 큰 통통 튀는 움직임·걷기 눌림·잔상 발자국(최대 18개, 750ms 자동 소멸)을 보여준다.
- 곰·고양이·토끼 NPC도 짧게 좌우 왕복할 때 진행 방향으로 좌우 반전하고 발을 구른다. 대화/지역 이동/기존 저장 형식은 그대로 유지한다.
- `scripts/check-walk-motion.mjs`에 좌/우/위/아래/정지 및 수평 방향 기억 검사 9개를 추가하고 빌드 검사에 포함했다.
- 한 장을 반전하는 방식이라 가방·파우치·목도리 같은 비대칭 장식도 화면상 좌우가 바뀐다. 추후 정식 4방향 캐릭터 원화를 만들면 이 한계를 해결할 수 있다.

## 구분해서 봐야 할 것

- 고화질 원화 배경 4장과 동물 친구 4명의 통일된 3D 동화풍 원화를 적용했다. 다만 **작물·건물·지형 가림 등은 임시 렌더링 상태**이므로 통일된 최종 2.5D 아트 완성본은 아니다. 향후 원화 레이어 분리, 농작물과 몬스터 스프라이트 제작 예정.

- 외부 CDN이나 유료 AI API 호출 없음. 앱 작동에 외부 서버 필수 아님.
- 아트·UI·라이브러리에서 SVG 렌더링 및 SVG 파일은 어떤 용도로도 사용 금지.

### v7 이동·카메라 안정화 (2026-10-28)
- 시작·지역 이동·기기 회전 시 카메라는 즉시 정렬하고, 걸을 때는 약 120ms 반감기로 부드럽게 따라간다.
- 목적지까지 약 75 게임 단위 이내에서 발걸음이 점차 느려지고 마지막 2.5 단위는 정렬된다. 실제 움직인 거리로 방향·발자국을 계산한다.
- 팝업을 열면 자동 이동을 중단해 대화나 가방 사용 중 계속 걷지 않는다.
- 4방향 여우 WebP 자산 유지. 모바일 원화·터치·저장 구조 불변. 공통 수학 함수는 테스트 스크립트에서 검사한다.
- 사이트의 운영 버전은 GitHub 작업 브랜치와 다를 수 있으므로 별도 재배포 확인 전에는 배포 완료로 표시하지 않는다.

### v8 (2026-10-28) — basic collision-aware walking
- Sprite-foot collision shapes for the town cottage foundation, the 12 farm soil mounds, and the lab/nursery stations. These are intentionally conservative gameplay approximations and are not pixel-accurate to the final illustrated backgrounds.
- Tap-to-move now calculates a detour using an A* walkable grid, checks each segment against the collision shapes, and redirects taps on an obstacle to a nearby walkable point.
- The computed route is cleared on zone change, modal opening, or blocked movement. Farming touch areas remain interactive, and saved-game fields/keys are unchanged.
- No SVG and no new large image assets. Real-device camera/collision alignment remains a required QA step; a successful GitHub build is not a live Sites redeployment.

### v9 (2026-10-28) — 경로 표시와 이동 구간 전체 충돌 검사

- 한 프레임의 이동 구간 전체를 6 단위 간격으로 검사하여 빠른 프레임에서 콜라이더를 뚫고 지나가는 위험 완화.
- 목적지 표시 유지 시간을 이동 완료 기준으로 바꾸고, 움직임 줄이기 설정은 정적인 표시로 처리.
- 전체 이동 경로 유효성 회귀 테스트 확대. 원화와의 충돌 정밀 정렬·실기기 QA는 별도 과제.

### v10 (2026-10-28) — 손그림 일러스트 UI 1차 통합
- 실제 일러스트 7종(총 약 78KB WebP): 16칸 아이콘 아틀라스, 양피지 패널, 나무·분홍·초록 버튼, 스크롤 트랙/손잡이. 인게임 간판도 이미지로 대체하며 실패 시 기존 도형으로 안전하게 표시.
- 상단 상태창, 4구역 이동, 하단 4메뉴, 가방·조합·부화·지역·도감·대화 팝업에 통일한 비트맵 화풍을 적용. 본문은 실제 브라우저 텍스트로 유지해 오타·가독성을 방지.
- 모달/버튼 기본 색의 대비와 44px 이상 터치 영역, 작은 모바일 화면/안전 영역, 키보드 포커스, 내부 스크롤바 테마를 개선.
- 게임 루트에서 우클릭/contextmenu·dragstart·비입력 요소 selectstart를 차단. 팝업 스크롤·버튼·입력란 선택은 유지. 브라우저 외부 요소는 제어하지 않음.
- 캐릭터, 전체 배경, 작물 렌더링 등 그림 보강은 계속 필요: 1차 UI 리스킨을 전체 게임 원화 완성으로 오인하지 말 것.
- SVG와 선형 시스템 아이콘 미사용, 저장 키/12칸/조합/부화/기존 main/Firebase 보존. 운영 사이트 v5와 개발 브랜치는 배포 확인 전까지 별도 버전.

### v10.1 — 심기·성장·수확 원화 교체
- 게임 내 12개 작물에 그림책 원화에서 추출한 4단계 성장 일러스트 `ui-crop-stages-v1.webp` (약 31KB)을 연결. 단순 타원·직선 새싹 대신 원화의 실제 잎·열매·흙 질감 적용.
- 성장 단계는 기존 18초 타이머를 그대로 사용하며, 수확과 씨앗/열매 계산 및 저장 데이터 변경 없음. 이미지 로드 실패 시 기존 그리기 방식이 대체로 작동.
- 농장과 전체 배경의 원화 위치를 실제 모바일 기기에 맞춰 보정할 필요가 있으며, 시설물/몬스터별 상세 일러스트는 추가 제작 범위로 유지.
