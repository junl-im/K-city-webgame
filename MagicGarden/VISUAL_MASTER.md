## 2. 비주얼 DNA — 새 자산의 필수 조건

1. **2.5D 핸드페인팅 동화풍:** 따뜻한 햇빛과 실내 등불, 구름/나무 그림자, 깊이가 느껴지는 마을·농장·실험실·둥지. 또렷하지만 각지지 않은 캐릭터와 물체 실루엣.
2. **캐릭터 일관성:** 여우·곰·토끼·고양이의 비율·복장·얼굴·소품을 모든 지역·대화·아이콘에서 동일하게 유지. 여우는 앞/뒤/좌/우 실제 4방향 원화가 기준. 걷기는 발걸음 프레임을 별도로 제작해 해결, 일시적 이미지 반전으로 완성이라 하지 않는다.
3. **조형 있는 작은 물체:** 씨앗, 작물의 4단계, 열매, 포션, 신비한 알, 몬스터, 흙, 나무·돌·유리에도 손그림 질감/입체 명암. **도형·기본 이모지·시스템 아이콘이 최종 그래픽에 남아서는 안 된다.**
4. **화면 밖/안의 일치:** 실제 플레이 월드의 원화 밀도와 메뉴·가방·퀘스트·도감·설정 창의 원화 밀도가 일치해야 한다. 아름다운 일러스트만 전시하고 게임 내부를 단순 도형으로 남기는 방식 금지.
5. **원화 아이콘과 버튼:** 마을/텃밭/실험실/연구소/가방/지역/도감/도움말/씨앗/열매/정수/알/닫기 등 아이콘 전부 투명 PNG/WebP. 나무, 분홍, 초록 버튼은 기본·눌림·선택·비활성 차이가 시각적으로 명확해야 한다. 작고 반복되는 요소에도 선형/SVG풍 금지.
6. **조화로운 마이크로 모션:** 귀여운 대기 호흡/눈 깜박임, 꽃잎, 물안개, 모닥불/솥/부화 빛 입자 등 세계 안에서 의미가 있는 움직임. 과도한 지속 광량·튀는 버튼 애니메이션 금지. `prefers-reduced-motion` 존중.
7. **화면 속 글자는 실제 HTML 텍스트:** 생성 이미지에 들어간 한글/숫자/가격을 UI 소스로 직접 쓰지 않는다. 별도 레이어 텍스트로 맞춤법, 줄바꿈, 확대, 접근성을 보장한다.

## 4. 화면별 한정된 목표

### 네 지역의 실제 플레이
- **마을:** 시안처럼 작은 집, 산책길, 나무, 꽃, 물가, 다리, NPC 대화; 발 위치 기준 충돌과 구조물 앞뒤 가림. 빈 초록 배경만 남기지 않는다.
- **텃밭:** 12칸 농지의 흙 깊이/울타리/물뿌리개/작물 단계별 생동감; 농사 조작이 그림과 정확하게 일치해야 한다.
- **조합 실험실:** 선반·유리병·마법 솥·등불·책·연금 효과와 실제 재료 조합 상호작용. 가짜 포션 수치를 그리지 않는다.
- **몬스터 연구소:** 둥지·알의 차가운/따뜻한 단계·부화 진척·빛·몬스터 입체 원화. 알 텍스처만 확대해 전체를 대체하지 않는다.

### UI와 콘텐츠
- **상단:** 꽃 장식 타이틀 + 캐릭터 초상 + 실제 보유 재료. 레벨·재화·보석은 시스템이 구현될 때만 노출.
- **이동:** 마을/텃밭/실험실/연구소 전용 일러스트 버튼. 실제 배경 위에는 배경을 가리지 않는 최소화 UI.
- **하단:** 가방/도감/지역/도움말/설정 등의 통일된 일러스트. 탭하면 정확한 콘텐츠로 열려야 함.
- **가방:** 실제 보유 수량·선택 상세·아이템 종별 원화, 스크롤 가능한 격자, 관련 행동 버튼.
- **조합:** 실제 인벤토리 재료 → 솥 → 완성품으로 단계적 연출. 조합 실패·재료 부족에도 동일한 패널 스타일.
- **부화:** 알 둥지 + 실제 남은 시간과 진행률 + 완성 애니메이션, 상태에 맞는 활성/비활성 버튼.
- **지도/도감/대화:** 일러스트가 먼저 보이고, 텍스트는 선명한 종이에 읽기 쉽게 배치.
- **퀘스트/상점/레벨/재화:** 시각적으로는 레퍼런스의 목표 범위지만 **현재 원본 게임의 구현 완료 기능이 아님**. 데이터·게임 규칙이 있는 실제 기능을 만든 후 도입. 무료 운영, 허위 유료 결제 버튼/가짜 수치/가짜 보상 금지.

## 5. UI/UX 하드 룰
- **금지:** SVG 파일/인라인 SVG/SVG 기반 아이콘, SVG처럼 보이는 선형 시스템 아이콘, 기본 이모지 픽토그램을 최종 아이콘으로 사용, 브라우저 기본 스크롤바, 일반 CSS 단색 캡슐 버튼으로 방치.
- **허용 파일:** 투명 WebP/PNG 등 검증된 라스터 원화. 원본 컷/아틀라스 순서를 설명하는 아트 메타 파일 유지.
- **스크롤:** 원화 기반 나무/꽃 스크롤 트랙·손잡이; 터치 스크롤, 키보드 탐색, 포커스 이동은 정상이어야 함.
- **우클릭/드래그:** 게임 화면 내부의 우클릭 메뉴, 자산 드래그·일반 텍스트 선택 차단. 입력 필드·파일 불러오기·실제 팝업 스크롤·접근성은 막지 않는다.
- **모바일:** 세로 320/360/390/430px, 가로 667/844px, 태블릿·PC 별도 검수. 터치 타깃 최소 **44 × 44px**, 터치 간격과 상·하단 safe area, 팝업의 최하단 버튼 접근성 최우선.
- **경량화:** 초기 구역만 지연 로딩하고 자산 WebP·공유 아틀라스 활용. 캐릭터+알+작물 애니메이션에서 메모리 급증 없이 부드럽게 렌더링.
- **기능 보존:** 12칸 텃밭, 조합, 부화, 몬스터, JSON 백업, 기존 `gomfox.magic-garden.prototype.v1` 로컬 저장 키 불변. Soul Online main/Firebase 무단 변경 금지.

## 8. 비주얼 절대 금지 원칙의 실행 기준 (v16, 2026-10-28)

- **SVG 전면 금지**: 확장자 `.svg`, 인라인 태그, data URI, SVG 스프라이트·로고·아이콘을 게임 소스/배포 자산에 반입하지 않는다. 코드·빌드의 `npm run guard`, `npm run guard:dist` 검사에서 적발 시 실패해야 한다.
- **'SVG처럼 보이는 디자인'도 금지**: 기본 브라우저 아이콘, Lucide/선형 시스템 아이콘, 임시 도형이나 이모지를 최종 버튼/인게임 그래픽으로 사용하지 않는다. 파일 확장자만 PNG라 하더라도 기본 벡터풍 디자인을 래스터화한 것이라면 원화 기준에 맞는 아트가 아니다.
- **원화 자산 우선**: 새 버튼·지도·작물·알·몬스터·재료 이미지가 필요하면 우선 그림책 화풍의 투명 PNG 또는 WebP 제작 → 원본 보관 → GitHub `public/assets/` 등록 → CSS/게임 로직 연결 → 시각 검사 순서로 진행한다. HTML 텍스트는 그림과 분리한다.
- **버튼 역할별 공식 v16**: 지역 이동=밝은 크림 표지판, 하단 메뉴=원목 배지, 분류 탭=평온한 양피지, 확인·조합·부화=분홍·금빛·연두색 행동 버튼. `src/button-art-v16.css` 및 `public/assets/ui-v16-*.png` 7종을 우선 기준으로 삼는다. 긴 나무/양피지 원화를 모든 버튼에 무분별하게 늘려 쓰는 방식은 금지한다.
- 새로 만든 원화가 예쁘더라도 실제 게임 화면과 모바일에서 여백/터치/색 대비가 맞지 않으면 미완성으로 표시한다.
