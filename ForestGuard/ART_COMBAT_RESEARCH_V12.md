© 2026 곰같은여우

## 기준과 디자인 원칙
- 기준: main의 ForestGuard v1.1.1. 기존 세이브 키 `gomfox.forestguard.v1`, 12개 스테이지, 영웅 1명 출전과 첫 공세 후 무료 영입 유지.
- 모든 SVG 금지. 외부 상용 게임 원화/코드 복사 없음. 새 원화 2종은 본 프로젝트 용도로 독자 생성.
- 타 프로젝트 폴더를 건드리지 않음. 개인 실명 표기 금지.
- 진행 목표: 첫 공세 부담 낮춤 → 용병 선택 → 일반-정예-중간보스-장 끝 보스의 리듬 형성.

## 유사 게임 · 기술 근거
1. Phaser 3 `Scale Manager` (공식): 고정 논리 캔버스의 FIT, EXPAND, RESIZE 모드 비교. 기존 FIT 유지로 캐릭터/충돌 판정 좌표 일관성 유지. https://docs.phaser.io/phaser/concepts/scale-manager
2. Phaser 3 `Input` (공식): mouse/touch 통합 `pointerdown`, 게임 오브젝트 `setInteractive()`. 적 터치 집중 사격에 적용. https://docs.phaser.io/phaser/concepts/input
3. MDN viewport units: `dvh`는 브라우저 도구막대 변화 대응, `svh`는 가장 안전한 고정 크기 대안. 브라우저·기기별 검증이 별도 필요. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length
4. MDN CSS `env()`: 노치/모서리/시스템 UI가 콘텐츠를 가리지 않도록 안전영역 반영. https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env
5. Kenney UI Pack (CC0): 버튼/패널 형태·터치 크기와 재료별 시각적 계층만 참고, 파일 미도입. https://kenney.nl/assets/ui-pack
6. rupertgermann/tower-defence: 여러 몬스터 타입과 웨이브/보스 조합 구조 연구, 외부 코드·원화 미도입. 원 저장소의 라이선스는 재사용 시 개별 확인. https://github.com/rupertgermann/tower-defence

## 밸런스 초안 (실측 승률 아님)
- 첫 공세 5~7마리 유지, 영웅 여우 한 명으로 시작.
- 중간보스: 각 스테이지 8공세면 5공세, 10공세면 6공세, 12공세면 7공세.
- 버섯 정예: 3의 배수 공세 단 중간보스·스테이지 최종 보스와 중첩 금지.
- 수호자 기본 체력 680 × [스테이지 13% 증가 + 지난 공세 10% 증가], 속도 17 + 스테이지당 0.8.
- 중간보스 충격파는 캐스팅 중 일제사격으로 취소 가능, 발동 시 -45; 성벽 도달 시 큰 피해.
- 영웅 DPS와 실제 처치 시간/성벽 누출율은 전 스테이지 시뮬레이션, 보스 완주 및 모바일 장기 테스트로 검증할 예정.

- 시나리오: 첫 공세→영입, 3공세 정예, 중간 공세 수호자 예고→스킬 저지, 장 끝 보스, 전체 12개 스테이지 및 저장 복귀.
