# 《곰같은여우의 마법정원》 MASTER GAME PLAN v0.1 — 구역 전환형 힐링 시뮬레이션

**문서 상태:** 2026-10-27 기획 초안 · 확정 전 · 실제 코드/배포 미실행
**시각 기준:** 사용자 제공 스크린샷(목조집·텃밭·개울·나무다리·폭포·풍차·숲의 따뜻한 3D 동화풍 디오라마)
**프로젝트:** 《곰같은여우의 마법정원》(가제)
**목표:** 무료 운영, 모바일 우선, 원화 품질, 지역 전환, 고양이·토끼·여우·곰 4종 시그니처 캐릭터의 일관성

## 1. 제품 방향
- 정원 1개가 아닌, 서로 이어진 여러 생활 구역을 오가는 힐링 생활 시뮬레이션.
- 3개 주요 놀이 축: 큰 정원(농사·꾸미기) ↔ 이상한 조합 실험실(합성) ↔ 몬스터 연구소(부화·육성). 수확 → 조합 → 발견 → 몬스터 성장 → 농사 도움의 순환.
- 플레이어가 원하는 구역에서 자유롭게 즐기는 탐색 중심. 에너지 과금, 유료 뽑기, 강제 광고, 촉박한 일일 기한 배제.
- 한 화면에 모든 기능을 우겨 넣지 않고 게임 내 길, 숲길, 다리, 문으로 구역을 전환. 바깥으로 나가지 않고 일관된 세계를 여행하는 느낌.

## 2. 세계 지도와 구역
| 코드 | 지역 | 대표 장면 | 주요 기능 | 연결 |
|---|---|---|---|---|
| TOWN | 중앙 마을 | 목조집·광장·벤치·상점 | 튜토리얼·NPC·가방·퀘스트 | FARM, HOME, BRIDGE |
| FARM | 큰 텃밭 | 밭·과수원·온실·풍차 | 씨뿌리기·물주기·수확·확장 | TOWN, FOREST, LAB |
| FOREST | 요정 나무숲 | 울창한 숲·버섯·숨은길 | 채집·희귀 씨앗·알 발견 | FARM, FALLS |
| FALLS | 폭포와 호수 | 절벽 폭포·개울·물레방아 | 낚시·수생 자원·비밀 동굴 | FOREST, BRIDGE |
| BRIDGE | 나무다리·강변 | 물 위 다리·작은 섬 | 구역 관문·탐험·보물 | FALLS, TOWN, NURSERY |
| LAB | 이상한 조합 실험실 | 유리병·반짝 가마솥 | 재료 조합·신규 아이템/씨앗 | FARM, NURSERY |
| NURSERY | 몬스터 연구소 | 부화실·온실형 서식지 | 알 부화·육성·도감·능력 | LAB, BRIDGE |
| HOME | 집·뒷뜰 | 방·뒤뜰·작은 연못 | 꾸미기·대표동물 교감·전시 | TOWN |
- 구역별 실제 걸어다니는 공간을 제공하고 장면 전환 시 방향, 음악, 소지품, 시뮬레이션 상태 유지.
- 초안 카메라: 고정된 입체 사선 시점(약 30–40°), 마우스/터치 이동, 확대/축소, 따라가기/카메라 이동.
- 구역 출입: 길 끝 또는 문 앞에서 0.3–0.8초 페이드 + 인접 구역 로드. 별도 지도에서 빠른 이동 지원. 숫자는 추정값으로 실제 모바일 테스트 후 조정.
- 각 지역은 독립 타일·배치·캐릭터 관리. 다른 구역에 있는 작물은 방문하지 않아도 시간에 따라 성장(저장 시각 기반으로 계산).

## 3. 시그니처 동물 4종
- 🦊 여우: 실험실 책임자, 호기심 많고 장난스러움.
- 🐻 곰: 정원 관리자, 듬직하고 느긋함.
- 🐰 토끼: 씨앗·조합 도우미, 빠르고 실수도 잦음.
- 🐱 고양이: 몬스터 교감·부화 도우미, 새침하지만 다정함.
- 4마리는 사이트 공통 정체성을 가진 '고정 NPC/플레이어 친구'이며 몬스터와 섞이지 않음. 정면/측면/후면, 걷기, 쉬기, 일하기, 기뻐하기 애니메이션 세트로 원화 일관성 관리.
- 플레이어는 대표 친구를 선택해 이동시킬 수 있고 나머지는 구역에서 일상 동작하는 방식 검토.

## 4. 핵심 게임 규칙
- 농사: 땅 고르기 → 심기 → 성장 → 수확. 초반 6종 작물과 2종 꽃, 2종 나무. 성장 시간은 짧고 방치 페널티 없음.
- 조합: 2~3개 재료를 넣고 실험. 도감에 신규 레시피 기록. 중복 시 판매·기증·꾸미기 재료로 활용.
- 몬스터: 8종 기본 + 성장/희귀 표현 다양화. 색상, 귀/꼬리/소품 변형; 외형은 유사종 반복으로만 구성하지 않음. 농사 도움, 채집 도움, 기상 변화 감지 같은 비전투 개성.
- 탐험: 비밀 길, 숨은 상자, 계절 행사, 4마리 캐릭터 개인 퀘스트. 지도는 단계 개방하되 불합리한 시간 게이트 없음.
- 꾸미기: 집 안, 집 뒤뜰, 밭 경계, 길·울타리·벤치·조명·연못 소품 설치. 충돌 판정 및 철거 복구.
- 저장: 손쉬운 자동 저장 + JSON 내보내기/불러오기. 방문 기기 간 자동 공유는 향후 선택 기능.

## 5. 모바일 UI
- 게임 화면이 중심(화면 면적 대부분). 상단엔 지역명/현재 재료만 작게, 하단엔 가방·행동·지도·도감 4개 핵심 버튼.
- 상황별 '심기/수확/대화/조합' 맥락형 행동 버튼. 탭·드래그·롱프레스 충돌 방지.
- 모달은 한 번에 1개, 안전영역(safe-area), 모바일 주소창 변화 대응. 화면 비율별 HUD 겹침 금지.
- 화면 이동은 로딩 상태와 귀여운 마스코트 애니메이션으로 연결; 작은 폰용 절전 옵션·효과 감소 옵션.

## 6. 기술 스택 권장안
**1순위: Vite + TypeScript + PixiJS 8 + Tiled/LDtk(맵 편집) + IndexedDB + PWA.**
- 이유: 현재 K-city-webgame 자체가 Vite/TypeScript/PixiJS 기반이라 일부 카메라·화면 스케일·터치 조작 노하우 재활용 가능. 단 MMO 전투 코드는 재사용하지 않고 독립 모듈 설계.
- 그래픽: 3D 소품 제작/다운로드 → Blender에서 통일된 사선 카메라로 렌더 → WebP/AVIF 스프라이트 아틀라스 + 깊이 정렬 → PixiJS로 2.5D 연출. 물/바람/발광 등 일부는 GPU 효과와 경량 프레임 애니메이션.
- 2순위: 풀 3D Three.js + GLB/압축 텍스처. 카메라 자유 회전이 필수일 때 비교 실험. 모바일 부담/애셋 공정 고려해 후순위.
- 데이터 구조: zones.json(연결), tiles/props.json(좌표), crops.json(성장), recipes.json(조합), monsters.json(능력), saveSchema.json(버전별 저장 데이터).
- 성능 목표(검증 전): 시작 구역 최초 압축 전송량 8 MB 안팎, 다른 구역 3–5 MB 안팎, 일반 모바일 30 FPS 이상 및 보급형 낮은 그래픽 설정. 동적 로딩, 아틀라스/캐시, 화면 밖 오브젝트 비활성화, 일부 애니메이션 제한.
- 오프라인 로컬 저장으로 서버 비용 최소화. 계정 연동/멀티플레이/실시간 랭킹은 MVP 범위 제외.

## 8. 개발 단계와 수용 기준
| 단계 | 작업 | 완료 판단 |
|---|---|---|
| 0 설계/자산 | 그래픽 스타일 가이드, 4마리 캐릭터 시트, 공통 타일, 2종 데모 소품 | 동일 시점/채도/비율 테스트 |
| 1 세로 슬라이스 | 중앙 마을+큰 텃밭 전환, 캐릭터 이동/카메라, 심기·성장·수확, 저장 | 모바일 실제 기기에서 정상 루프 |

| 3 월드 확장 | 숲·폭포·다리·집/뒤뜰, 탐험/꾸미기/퀘스트 | 모든 구역 왕복·저장 복원 |

- 예상 제작 난이도: 프로토타입은 주 단위, 전체 그래픽/맵 8개 포함 정식 초판은 다주~수개월 이상. 이는 팀 규모/원화 확보와 QA 수준에 따라 크게 변동되는 추정.

## 9. GitHub 사용 및 보존 정책
- 점검한 기존 저장소: https://github.com/junl-im/K-city-webgame (공개, main, 2026-10-27 기준 파일 약 1,920개).
- 현재는 Soul Online Alpha(패키지 버전 1.41.0) 소스가 존재하고 PixiJS 8/TypeScript/Vite/Firebase/Firestore 구성 및 GitHub Actions 빌드가 설정돼 있음.
- 기존 자료는 현재 삭제·초기화 금지. 먼저 백업 브랜치와 태그를 만들고 배포 URL/Firebase 연동/용량·라이선스를 감사. 새 게임은 계획용 별도 브랜치에서 시작.
- 이후 선택지 A: 저장소 이름 변경 + 기존 앱 아카이브 후 메인 교체. 선택지 B(보존성 우수): 기존 저장소 유지 + 새 전용 저장소 생성. 사용자는 A를 선호하나 최종 삭제 대상과 새 이름은 확인 필요.
- 제안 저장소 이름: GomFox-MagicGarden (가칭). GitHub 저장소 설정에서 이름 변경은 admin 권한으로 가능. 단 GitHub Pages 프로젝트 URL과 CI/로컬 원격 주소는 변경 후 점검 필수.
- AI 놀이터 허브(junl-im/meta): 나중에 AIPlayground/MagicGarden 독립 빌드로 결합, ai-cleaner 홈에 새 일러스트 카드 추가. 첫 릴리즈는 새 프로젝트 단독 URL로 QA 후 허브에 연결.
